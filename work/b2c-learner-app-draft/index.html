B2C Learner App

Training that feels native on phone and web

2024 Contributors: Me (Product Designer), Design & Flutter

3Surfaces shipped
1Shared system

I designed the B2C learner side of the product so the same journey felt natural on web and on a Flutter mobile app.

The Problem

Learners were the end customers, but the experience still felt like a B2B admin tool squeezed onto a phone. Web and mobile drifted apart, and everyday tasks — continue learning, join live class, pick up where you left off — asked for too much patience.

Admin DNA on mobile

Dense layouts and enterprise patterns didn’t belong in a learner’s pocket.

Split surfaces

Web and Flutter each reinvented flows, so the product never felt like one app.

The B2C side had to feel light and personal — without breaking the white-label system the B2B side depended on.

Good

  • Clear learner jobs: learn, continue, attend live
  • Flutter already in production for mobile
  • Shared brand tokens from the redesign

Bad

  • Screens mirrored the admin panel
  • No mobile-first information hierarchy
  • Web and app advancing on different schedules

01

We rebuilt the mobile learner app around continue learning, live classes, and a home that fits one thumb.

Primary actions moved to the bottom of the screen. Course cards carried progress and next lesson without opening a settings drawer. Live and upcoming classes sat next to Continue Learning so a learner could open the app and know what to do in the first glance.

02

We mirrored that same system on web so switching devices never felt like switching products.

Web kept the learner jobs and visual language of the phone, not the density of the trainer admin. Spacing, type, and component rules came from one design system, themed per white-label brand, so Flutter and web could ship in parallel without redrawing every state.

The Result

The B2C surface finally felt like a consumer product — on phone and on web — while staying inside the same white-label system the enterprise side used to sell.
